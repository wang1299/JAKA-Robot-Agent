# Agent 与机器人任务回放

回放让没有机器人、GPU 或模型服务的开发者看见完整任务过程：Agent 工具调用 → 计划确认 → 机器人动作与观察 → 任务反馈。默认决策和观察均为预设样例；页面明确标记数据来源。

## 启动和操作

```bash
python -m pip install -e .
jaka-agent --replay --port 8080
```

打开 [http://127.0.0.1:8080/replay](http://127.0.0.1:8080/replay)。默认只监听本机，数据写入当前目录的 `data/replay/`；可用 `JAKA_DATA_DIR` 指定其他目录。原有真实会话默认不会被载入。

1. 选择案例，点击“让 Agent 生成计划”。此时只查询资源、生成任务卡，机器人位置不会改变。
2. 核对步骤，点击“确认计划并执行”。地图展示位姿与轨迹，右侧记录动作和观察。
3. 迎宾任务到接人点后停下。可拒绝当前照片，或确认后继续引导。
4. 执行结束后点击“让 Agent 汇报执行结果”，查看基于任务状态的回答。运行时可点击“停止任务”。

| 案例 | 观察重点 |
| --- | --- |
| 参考图寻物 | 候选点未匹配后继续搜索，在会议桌匹配后结束 |
| 迎宾与人工确认 | 接人点等待、拒绝后更新确认照片、确认后引导 |
| 导航失败反馈 | 导航中止后不再拍照，Agent 汇报中止状态 |
| 缺少参考图 | 请求补充图片，不创建动作任务 |

每次新案例创建独立会话；一次只执行一个任务。刷新保留当前会话标识。任务和媒体使用正常存储机制，页面时间线只保存在当前进程内，重启后不会重建旧时间线。

## 运行模式

| 启动参数 | 决策来源 | 动作与观察 | 用途 |
| --- | --- | --- | --- |
| `--mock` | 模拟回复 | 部分模拟流程 | 完整终端界面开发 |
| `--replay` | 固定案例预设工具调用 | 合成回放适配器 | 任务展示与控制契约验证 |
| `--replay --replay-model` | 已配置的真实决策模型 | 合成回放适配器 | 检查模型技能选择与工具调用 |
| 不带以上参数 | 真实模型 | 底盘、相机与视觉服务 | 实机任务 |

`--replay-model` 会访问模型服务，需要先完成[模型部署](models.md)并配置本地连接。所有回放模式都禁止真实硬件执行；视觉比对仍用预设标注，不能用回放评估视觉模型。自由输入可在完整任务终端使用真实决策模式；默认预设决策只响应固定样例。

## 固定任务契约评估

```bash
python tools/evaluate_agent.py --mode replay
# 需要已配置的真实决策模型；机器人反馈仍为合成样例
python tools/evaluate_agent.py --mode model --config configs/model_config.local.json
```

评估包含上表四类任务和“导航中取消”，默认报告写入 `tests/artifacts/agent-evaluation.json`。评估程序会明确确认自己创建的回放任务；网页仍要求手动确认。每个案例之间重置演示位姿，异常只记录类型，避免把私有模型地址写入报告。

报告提供逐案例检查、通过数、决策请求耗时和中位数。默认模式的耗时是预设工具回放开销，`5/5` 只表示这五个固定软件契约通过；模型模式也只反映这一小组任务的工具调用表现。真实模型规划质量、视觉准确率、导航成功率与实机延迟需要另行采样和验收。

## 实现与扩展

`src/jaka_agent/replay/fixtures.py` 定义案例、演示地图、合成图片和预设决策；`replay/state.py` 提供导航和视觉反馈适配器。AgentRunner、技能入口、计划校验、所有者核对、照片确认与取消机制沿用主系统。独立页面位于 `web/templates/replay.html`，只在回放服务中开放。

新增案例需要同时提供输入、观察反馈和可验证的预期行为；不要把预设成功结果写成模型能力。回归覆盖位于 `tests/test_agent_robot_replay.py`。
