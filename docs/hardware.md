# 硬件准备

本项目的实机环境包含 JAKA 移动底盘、机器人侧计算设备，以及头部和手部各一台 Orbbec Gemini 2 L 相机。网页任务主要调用底盘导航、相机采集和语音；机械臂控制需要单独准备厂商 SDK，当前任务流程没有接入机械臂抓取。

## 系统与设备接口

| 部件 | 本项目接口 | 部署时准备 |
| --- | --- | --- |
| 移动底盘 | `hardware/navigation.py` 的 TCP/HTTP 驱动 | 本机底盘地址、端口、导航地图和可达点 |
| 头部、手部相机 | `hardware/camera.py`，Orbbec Python SDK | 两台相机的设备识别、彩色/深度取帧和序列号映射 |
| 麦克风与扬声器 | `hardware/voice.py` | Linux 音频设备、识别与合成模型 |
| 机械臂与头部控制 | 厂商 SDK 示例，独立于任务服务 | 与操作系统、架构和控制器匹配的 SDK |
| 建图 | `mapping/bridge.py` 与外部建图服务 | 相机数据、机器人位姿及场景图接口 |

网页 Mock 与离线测试可在 Windows 上运行；设备侧示例和语音路径包含 Linux 组件，例如终端输入、`aplay` 与固定模型目录，不能直接认为整个实机环境可跨平台运行。厂商 SDK 应按具体操作系统选择，避免混用 Windows 与 Linux 的二进制库。

## 双相机检查

先使用 [Orbbec SDK 发布页](https://github.com/orbbec/OrbbecSDK/releases)提供的工具检查设备与图像，再准备 [Orbbec Python SDK](https://github.com/orbbec/pyorbbecsdk)。Python SDK 有不同主版本和设备支持范围，安装前核对相机固件、操作系统、架构与 Python 版本；本项目不会自动安装或升级设备固件。

在准备好 SDK 的设备环境中检查枚举结果：

```bash
python -c "from pyorbbecsdk import Context; print('device_count=', Context().query_devices().get_count())"
```

本项目的双相机配置预期枚举到 2 台设备。分别确认头部与手部画面，再设置 `JAKA_HEAD_CAM_SN` 和 `JAKA_HAND_CAM_SN`；仓库默认值来自开发设备，应替换成自己的设备序列号。模型视觉判断前，先确认彩色帧和深度帧均能稳定读取。

## 上电与运行顺序

1. 按设备操作规程上电，等待设备完成初始化；开发设备的记录以指示灯变为白色作为就绪提示，其他型号按对应手册确认。
2. 接入自己的机器人网络，使用设备管理界面确认底盘状态，并完成现场扫图、修图和定位。
3. 检查双相机取帧、语音设备及本地模型服务，再启动网页服务。
4. 先核对地图坐标和目标点，确认任务卡后执行短距离任务，再验证寻物与迎宾流程。

设备管理地址、网络名称、登录凭据与 SDK 安装包由部署者在本地保存。不要把现场账号、密码、个人照片或设备管理截图提交到仓库。

## 关闭与维护

先在网页取消任务并确认底盘停止，再退出任务服务；备份会话、媒体、地图与标定后，按设备操作规程关闭控制系统和电源。机械臂与底盘各有独立的控制接口，应按对应手册操作。

机械臂 Python 接口可参考 [JAKA Python SDK 文档](https://www.jaka.com/docs/guide/SDK/Python.html)。底盘协议需使用与设备固件匹配的厂商《软件 API 手册》，不要把机械臂 SDK 当作底盘导航驱动。
