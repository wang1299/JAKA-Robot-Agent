# Agent：从语言需求到机器人技能

Agent 负责理解需求、查询证据、选择技能并生成待确认计划。机器人执行器负责动作与任务结果；Agent 汇报执行情况时读取任务状态，不能凭模型回答宣告移动或寻物成功。

## 一次决策

1. `agent/service.py` 载入当前会话、参考图和任务上下文。
2. `AgentRunner` 调用允许的工具。`get_skill_context` 检查技能输入和地图配置；地图查询工具返回真实 `ann_id`、名称与坐标。
3. 模型选择 `plan_*` 技能工具。`prepare_skill` 校验参数类型、目标有效性、必需的参考图和返程要求。
4. 任务服务发布任务卡并结束本轮规划。用户确认后，任务执行器才允许执行。
5. 执行后再次提问，Agent 通过 `get_robot_status` 获取状态；任务状态汇报保留中止、出错、未找到和无法确认等结果。成功寻物回复包含执行器记录的发现位置。

工具结果作为数据传给模型；工具调用记录和任务卡供用户核对。系统不执行模型生成的任意代码，也不把工具调用记录当成模型内部思维过程。

## 技能契约

| 技能工具 | 必需输入 | 完成依据 |
| --- | --- | --- |
| `plan_navigate` | 地图目标列表、明确的返程参数 | 指定目标导航完成，按要求返程 |
| `plan_find_object` | 寻物需求、参考图 | 现场比对匹配，或候选点检查结束 |
| `plan_welcome` | 人物参考图、接人点、送客点 | 主人确认现场照片，并完成引导 |
| `plan_patrol` | 至少两个地图点、巡逻轮次 | 检测到变化或有限轮次结束 |
| `plan_inspect_location` | 地图目标、观察问题 | 到点观察完成，按要求返程 |

定义位于 `src/jaka_agent/agent/skills.py`，包括输入结构、步骤、完成标准和失败规则。地图默认点来自 `skill_defaults`，有多个候选时需要澄清。房间号不能直接充当导航目标编号。

## 环境证据与不确定性

语义地图回答“哪里有可访问的候选地点”，现场图回答“此刻看到了什么”。地图中的物品记录不等于现场发现；历史照片不等于实时观察。缺参考图、目标有歧义或视觉无法确认时，应请求补充或保留不确定结果。

寻物候选搜索和迎宾等待由技能执行器推进。当前版本没有在每个动作后重新调用 LLM 生成下一动作；需要改变高层计划时重新发起需求并确认新任务。

## 模型与回放

真实模式沿用双模型路由：决策模型选择工具，视觉模型分析图像。支持 JSON 工具协议和兼容的原生工具调用接口，具体配置见[模型部署](models.md)。协议兼容不保证某个模型能稳定选择正确技能，需要运行独立评估。

`--replay` 使用固定案例的预设工具调用，仍经过同一个 AgentRunner 与技能入口。`--replay --replay-model` 将决策接到配置的真实模型，机器人动作和视觉判断仍来自合成回放适配器。两者均不驱动实际底盘；详见[任务回放与评估](replay.md)。
